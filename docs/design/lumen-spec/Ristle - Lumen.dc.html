Exploration · provider spaces · settings
Provider spaces: plugins declare views — a feed, charts, a profile — as pure data: the same result rows used everywhere, plus social counts (follows, likes, reposts). Behavior rules
Mobile: tap plays; long-press = context menu. Desktop: click selects, double-click plays, right-click = menu — plugins can't override either, only add ≤ 2 menu items.
Desktop selection works like a file browser: Shift-click extends a range, Ctrl / Cmd-click toggles single rows. Menu actions apply to the whole selection.
Title, artist and album are links — underlined on hover, each navigates to its page. Tracks can have multiple artists, each its own link.
Drag: desktop — click-drag anywhere on the row, no handle; mobile — handle in queue & edit mode, or long-press 250 ms. Lifted rows scale 1.015 + shadow.
Source dot is mandatory — the one prop plugins cannot hide.
No play overlay on artwork, ever — the row itself is the play target (API terms).
Min hit target 56 px on mobile, 44 px desktop compact.
In React Native this is one <TrackRow> with platform tokens for radius and density — the same component the Feed, queue and playlists in this spec already picture.
